# Upstream source

The canonical `lienzo-gwt/src/main/java/com/ait/lienzo` tree comes from
[Apache KIE Lienzo core](https://github.com/apache/incubator-kie-tools/tree/f774fc229484155e23b7aa07107474eaa3eca8c3/packages/stunner-editors/lienzo-core),
revision `f774fc229484155e23b7aa07107474eaa3eca8c3`. The initial import contains 530 production Java files and six upstream test classes.
The TeaVM adaptation compiles the same 530 production sources.
The pinned source is a reproducible baseline, not a claim to track the latest KIE revision.

Upstream headers are retained. `LICENSE` supplies Apache License 2.0; `NOTICE` retains the KIE
notice and relevant Lienzo and GWT attributions from the repository-wide licensing files.
No KIE Stunner application, BPMN editor, fonts or showcase assets are included.

Local changes use canonical inherited Elemental2 type imports and correct the media preload
property spelling. TeaVM sources are generated by the existing `teavm-compat` source adapter.
They are not maintained as a second copy of the library.

## Undo and redo

The selected Lienzo core has no general command history or undo/redo manager. Its public
`DragContext.reset()` restores a node's pre-drag position and is retained. KIE Stunner implements
application command history above Lienzo; that separate API is not part of this core port.
A future optional history adapter should preserve these existing interaction APIs.

## Static analysis

`verify` fails on unreviewed high-priority SpotBugs findings. The narrow filter in
`config/spotbugs-compatibility.xml` records preserved public factory/configuration fields,
exact coordinate/channel comparisons, and upstream global JavaScript integration state.
These exceptions are not a claim that the global JsCanvas integration is safe for multiple
independent canvases. Isolating that state without breaking consumers needs separate API work.
Lower-priority findings remain in the generated reports for further review.

The port replaces two unnecessary boxed-number parses and fixes selection-handler cleanup:
upstream guarded cleanup with a start-handler field that was never assigned, so registered
end/click handlers were never removed there.
